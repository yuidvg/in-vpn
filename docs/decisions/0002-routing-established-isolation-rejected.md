# 0002: 転送の成立と隔離方式の不合格を分ける

日付: 2026-10-07。状態: [第2報](../report-2.md)による部分判断。目的・R1〜R8は維持する。

NEで受けた通常TCP/UDPを認証付きローカル中継からSOCKS、userspace WireGuardへ送る方式は、測定した条件で成立した。2本のローカルWireGuardにも同じ実行ファイルを実行単位で分けられた。転送アダプターの検討は継続できる。

POSIXセッションID単独は、子のsetsidで所属を失うため完全な子孫追跡に使わない。Endpoint Securityは権限不足で実験できておらず、成功としない。

標準DNSの要求元を取得してVPN別に中継しても、共有された回答が別VPN・通常セッションに返る。TTL=0も今回の直後再利用には対策にならなかった。共有キャッシュと要求集約の隔離を解決するまで、DNSの方式を確定しない。

透明Providerのクラッシュ後に直接通信を再現した。追加した単純なContent Filterは正常転送も止め、自身のクラッシュ後は直接通信を許した。sandboxのnetwork-outbound禁止も正常な透明転送を止めた。これらの単純な候補をfail-closed境界には採用しない。

次の関門は、承認済み権限での子孫イベント実験、DNS共有状態の隔離、正常系と故障系を両立する遮断方式、独立した外部VPN2本での試験である。すべての必要な性質を同時に実証するF08は未完了。プロキシ対応wrapperへの目的変更や、保護できない通信の暗黙許可は行わない。
